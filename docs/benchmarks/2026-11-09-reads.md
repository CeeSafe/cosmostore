# Reads on the event loop, 9 Nov 2026 (M4 slice 3)

Reads without worker threads where they do no I/O (ADR-0023), compared with group commit
(`2026-11-09-group-commit.md`).

## Environment

| | |
|---|---|
| What | M4 slice 3: HEAD, the GET plan and bucket lookups on the event loop; inline bodies sent in one write; ceesafec 0.24.1, default StoreConfig |
| Host | Apple M1, darwin 27.0.0 (macOS laptop, internal SSD, `F_FULLFSYNC`) |
| Client | `tools/bench` (go1.27.3), loopback, plain HTTP, SigV4 with UNSIGNED-PAYLOAD |
| Run | `tools/bench.sh -sizes 0,128,1024,4096,65536,1048576 -concurrency 1,8,32,128 -ops 1000` |
| Seed | 1; every GET body checked by MD5; no errors; fsck clean afterwards |
| Raw data | `2026-11-09-reads.json` |
| Load | Load average 4 to 6.5; other sessions ran mostly remote work. The run's first phase, 0 B PUT at concurrency 32, gave 2,705/s; two reruns of that row alone gave 3,111 and 3,307/s (PUT is unchanged by this slice). |

## Findings

1. **HEAD no longer takes a thread.**

   | HEAD | Concurrency 1 | 8 | 32 | 128 |
   |---|---|---|---|---|
   | Group commit | 9,600 to 11,000/s | about 20,900/s | 15,800 to 17,300/s | 9,200 to 10,400/s |
   | Now | 13,000 to 15,100/s | 34,000 to 39,500/s | 37,000 to 42,000/s | 37,000 to 44,000/s |

   p99 at concurrency 32 is 1.2 to 2.1 ms, and HEAD no longer falls off at 128. One phase is an outlier: 128 B at
   concurrency 1 gave 4,765/s (p99 1.3 ms), where every other size gives 13,000 to 15,100.
2. **Small GETs make one worker-thread call instead of three.**

   | GET at concurrency 32 | Group commit | Now |
   |---|---|---|
   | 0 B | 15,700/s | 35,800 to 39,600/s (no body, so no thread) |
   | 128 B to 4 KiB | 11,100 to 12,100/s, p99 4.8 to 7.3 ms | 15,500 to 16,200/s, p99 3.1 to 3.3 ms |
   | 64 KiB | 6,600/s | 8,000/s |

3. **GET at concurrency 128 is still about 9,000/s,** with a p99 of 18 to 59 ms. The inline record is read on a worker
   thread while the store's lock is held, so reads with bodies still serialize on the lock and a thread start each.
   Reading the record without the lock needs segment pins (ADR-0023, "Rejected").
4. **Unchanged, as expected:** PUT (3,100 to 3,300/s at 32 clients), DELETE (about 200/s), and 1 MiB (PUT 173 MiB/s,
   GET 946 MiB/s at concurrency 32).
